Tool access for Claude

This app runs on your computer. It keeps its files in its data folder and computes the map itself, so its answers are current whether or not this page is open. An MCP client, such as Claude Code, connects to the app at http://localhost:4787/mcp and gets the operations below as tools.

claude mcp add --transport http dependency-map http://localhost:4787/mcp

A client can also start the app itself, over standard input and output: claude mcp add dependency-map -- node <path to DependencyMap>/server.js --stdio. The page is then served too, when the port is free.

How the map is made

Every IRI that is the subject of a statement in a loaded file is a term. Each statement from a term to a term is an edge, and the property of the statement is the name of the edge. A value inside a blank node (a list or a class expression) belongs to the statement that holds the blank node. The files say which edges are references: rdfs:seeAlso and each property that the files make a subproperty of it. References are drawn when you select them, but they are not used for cycles or tiers. A cycle is a strongly connected component, and it is generated as one unit. The tier of a term is the length of the longest dependency path below it.

These notes are the text of the first version of this document, of 2026-10-31. They describe four files: the rdf and rdfs files from w3.org, owl.ttl and FOAF. The counts and tiers in them are not the counts and tiers of the files that are loaded now.

What has to happen first

  1. The root unit: rdfs:Resource, rdfs:Class and owl:Class. They depend on each other, so the translator's first rule produces all three together. Nothing else can be generated before them.
  2. The rule selectors come next: rdf:Property, rdfs:Datatype, rdfs:Literal, owl:Ontology and owl:Thing (tier 1), then owl:ObjectProperty, owl:DatatypeProperty and owl:AnnotationProperty (tier 2). Every term in the files is typed by one of these. That rdf:type tells the translator which codegen rule applies, so the rules for these classes have to exist before any other term is translated.
  3. The structural properties are in tier 2: rdf:type, rdfs:subClassOf, rdfs:subPropertyOf, rdfs:domain, rdfs:range, rdfs:label, rdfs:comment, rdf:first, rdf:rest and rdf:nil. They are the predicates that every later term is stated with.
  4. Then each tier in turn, one unit at a time, with the order inside a tier left free. In FOAF, foaf:Agent is tier 1, the cycle of foaf:Person, Document, Organization and Project is tier 2, and foaf:knows and foaf:name are tier 3.

Ordering edges: rdf:type, rdfs:subClassOf, rdfs:subPropertyOf, rdfs:domain, rdfs:range and the OWL axioms. rdfs:isDefinedBy, owl:imports and owl:versionIRI name the ontology a term belongs to (its module, per D8 A), so they are drawn but left out of the order. Counted with them, the four ontology nodes join the root cycle.

Where things are tied together

The edges that become Swift structure, subClassOf and subPropertyOf (protocol inheritance, D1 A) and domain and range (typed members, D4 A), contain no cycles anywhere in the four files. Every cycle runs through rdf:type, through rdfs:isDefinedBy, or through a symmetric OWL axiom (owl:disjointWith, owl:inverseOf).

tier 0 The root: rdfs:Resource, rdfs:Class, owl:Class

rdfs:Class is an instance of itself. Resource is an instance of Class, and Class is a subclass of Resource. The W3C files alone make a two-term cycle. FOAF's file adds owl:Class to it, because it asserts that rdfs:Class is an owl:Class while owl.ttl makes owl:Class a subclass of rdfs:Class.

rdfs:Resource a rdfs:Class ;                        # rdfs.ttl line 9
rdfs:Class a rdfs:Class ;                           # rdfs.ttl line 14
	rdfs:subClassOf rdfs:Resource .
owl:Class a rdfs:Class ;                            # owl.ttl line 83
     rdfs:subClassOf rdfs:Class .
<owl:Class rdf:about="http://www.w3.org/2000/01/rdf-schema#Class"/>   # index.rdf line 38

tier 2 FOAF's disjoint classes: Person, Document, Organization, Project

Each one states owl:disjointWith against the others: Person and Document with Organization and Project, and Organization and Project with Person and Document (index.rdf lines 69–102). This is the only cycle among FOAF's classes, and it runs through disjointWith alone. The subClassOf edges from Person and Organization to Agent are acyclic.

tiers 3–4 FOAF's four inverse pairs

made and maker, depiction and depicts, page and topic, and isPrimaryTopicOf and primaryTopic. Each property names the other through owl:inverseOf (index.rdf lines 377–530). Each pair is one unit.

module The ontology nodes

Every rdfs term is rdfs:isDefinedBy rdfs:, and that ontology is an owl:Ontology, which is an rdfs:Class. Counted with isDefinedBy, rdfs: and owl:Ontology join the root cycle, making it five nodes. That is why isDefinedBy is treated as module membership, not as an ordering edge.

owl.ttl uses three different IRIs where the other files use one. It declares its ontology as <http://www.w3.org/2002/07/owl>, with no #, and gives that same IRI as its own owl:versionIRI. Its terms are rdfs:isDefinedBy <http://www.w3.org/2002/07/owl#>, which nothing declares. It owl:imports <http://www.w3.org/2000/01/rdf-schema>, also without a #, while rdfs.ttl declares its ontology as <http://www.w3.org/2000/01/rdf-schema#>. The map keeps them as separate nodes, as the files have them. Three owl terms are also isDefinedBy OWL 2 TR documents.

<http://www.w3.org/2002/07/owl> a owl:Ontology ;             # owl.ttl line 9
     owl:imports <http://www.w3.org/2000/01/rdf-schema> ;      # owl.ttl line 35
     owl:versionIRI <http://www.w3.org/2002/07/owl> ;          # owl.ttl line 36

What this means for step 1

Step 1 per the direction doc and PLAN.md WP-P: OWL declarations generate Swift types, subClassOf becomes protocol inheritance, and domain and range become typed properties. The data says the following about each decision.

D1 A · subClassOf is protocol inheritance

The subClassOf graph is acyclic in all four files, so every protocol refines protocols that already exist. Several parents do occur: foaf:Person is a subclass of both foaf:Agent and geo:SpatialThing, which only protocol inheritance can carry.

D7 A · Resource and Thing are one root protocol

The root cycle exists only through rdf:type. Its subClassOf part is a plain chain: owl:Class, then rdfs:Class, then rdfs:Resource. Classes are resources that get translated (D7 A), so their rdf:type edge is the instance-of relation, and it selects the codegen rule. That makes the root one bootstrap unit that the translator's first rule emits, not something to hand-type (rule 0).

D4 A · a property is a requirement on its domain's protocol

foaf:knows has domain and range foaf:Person, so it lands on Person, typed Person. foaf:name has domain owl:Thing (index.rdf line 279), so under D7 A and D4 A it lands on the root protocol, not on Person. It also has range rdfs:Literal and refines rdfs:label. STEP-1-PLAN.md currently puts name on PersonIndividual, but the data puts it on the root. alice.name still works, because Alice conforms to the root.

D6 A · literals

foaf:name's range is rdfs:Literal, which is tier 1, so a plain literal maps to String (rule 20) as soon as the literal rule exists. One referenced datatype, xsd:nonNegativeInteger (the range of OWL's cardinality properties), is not declared in any of the four files.

D8 A · isDefinedBy is the declaring module

There are 189 isDefinedBy edges: 22 to rdf:, 15 to rdfs:, 77 to owl:, 72 to foaf: and 3 to OWL 2 TR documents. Treating them as the module keeps them out of the order, and the modules match the four files. For OWL, the module IRI (owl:, with #) differs from the declared ontology IRI (no #). Mapping isDefinedBy to the module has to account for both IRIs.

Open for Charles · undeclared targets

Step 1's closure reaches four classes that none of the four files declares: schema:Person, contact:Person, dcterms:Agent (through owl:equivalentClass from Person and Agent) and schema:CreativeWork (from Document). None of the decisions say what owl:equivalentClass becomes when the other class has no declaration, so this is left for you.
